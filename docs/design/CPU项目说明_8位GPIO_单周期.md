# 16位单周期 CPU 项目说明

## 1. 项目目标

本项目计划在 EES331 开发板的 Zynq-7020 FPGA 可编程逻辑（PL）中，使用 HDL 设计并实现一个16位、非流水线、单周期软核 CPU。CPU 能够执行基本数据传送、算术、逻辑、比较、跳转和独立端口 I/O 指令，并通过8个方向可配置的 GPIO 引脚与外部设备交互。

本项目实现的是自定义指令集的软核 CPU，不是修改 Zynq 的 PS 中已有的 ARM 处理器。以下内容描述设计方案，不表示 RTL、仿真或上板验证已经完成。

## 2. 系统组成与边界

```text
FPGA PL
├── CPU Core
│   ├── Controller：字段提取、操作码译码、组合控制信号生成
│   └── Datapath：寄存器组、立即数扩展、MUX、ALU、Z、PC及下一PC逻辑
├── Instruction Memory：256 × 16位，组合读
└── GPIO Peripheral
    ├── 端口译码和读写控制
    ├── GPIO_OUT：8位输出寄存器
    ├── GPIO_DIR：8位方向寄存器
    ├── 输入同步器及GPIO_IN读取路径
    ├── I/O读取选择器
    └── 8个双向I/O缓冲器 ↔ FPGA物理引脚 gpio[7:0]
```

指令存储器和 GPIO 外设均位于 CPU Core 边界之外，但计划实现在同一颗 FPGA 的 PL 内。它们与 CPU 的连接为内部信号，不因跨越 CPU 边界而占用 FPGA 外部引脚。

CPU 采用独立的取指接口和 I/O 接口，当前并非一条统一共享总线。当前 ISA 不包含 LDR/STR，未实现普通数据存储器读写，因此不能仅因 Memory 在 CPU 外就将本版本称为完整的冯诺依曼存储系统。若以后要求指令与数据共用存储器，需要另外确定访存指令、端口及访问时序。

## 3. 核心参数

| 项目 | 当前方案 |
|---|---|
| 实现位置 | EES331开发板，Zynq-7020 PL |
| 数据位宽 | 16位 |
| 指令位宽 | 16位 |
| 通用寄存器 | R0～R3，共4个，每个16位 |
| PC | 8位，按16位指令字寻址 |
| 指令存储容量 | 256 × 16位 |
| 标志寄存器 | 1位Z，仅CMP更新 |
| 执行方式 | 单周期、非流水线 |
| I/O寻址 | 独立8位端口地址 |
| CPU I/O数据总线 | 16位 |
| GPIO物理信号 | 8个双向可配置引脚，不含时钟和复位 |

## 4. 指令集与编码

### 4.1 字段定义

| 位段 | 名称 | 含义 |
|---|---|---|
| [15:12] | Opcode / Operation Code | 操作码 |
| [11:10] | Rd / Destination Register | 目标寄存器编号；双操作数运算中也提供操作数A |
| [9:8] | Rs / Source Register | 源寄存器编号 |
| [7:0] | imm8 / port | 立即数、绝对跳转目标地址或I/O端口地址 |

不同指令不一定使用所有字段。未使用字段建议在汇编编码时置零。立即数运算采用零扩展；跳转目标直接使用8位imm8，不是相对PC的偏移量。

### 4.2 当前编码方案

| Opcode | 指令 | 操作 |
|---|---|---|
| 0000 | MOV Rd, #imm8 | R[Rd] ← 零扩展imm8 |
| 0001 | MOV Rd, Rs | R[Rd] ← R[Rs] |
| 0010 | ADD Rd, #imm8 | R[Rd] ← R[Rd] + 零扩展imm8 |
| 0011 | ADD Rd, Rs | R[Rd] ← R[Rd] + R[Rs] |
| 0100 | XOR Rd, Rs | R[Rd] ← R[Rd] XOR R[Rs] |
| 0101 | SUB Rd, Rs | R[Rd] ← R[Rd] − R[Rs] |
| 0110 | CMP Rd, Rs | Z ← (R[Rd] == R[Rs])，不写Rd |
| 0111 | AND Rd, Rs | R[Rd] ← R[Rd] AND R[Rs] |
| 1000 | JZ #imm8 | 若已保存的Z=1，则PC ← imm8 |
| 1001 | OR Rd, Rs | R[Rd] ← R[Rd] OR R[Rs] |
| 1010 | JUMP #imm8 | PC ← imm8 |
| 1011 | INP Rd, port | R[Rd] ← I/O读数据 |
| 1100 | OUP port, Rs | 向I/O端口写入R[Rs] |
| 1101～1111 | 保留 | 本版约定无写入副作用，PC顺序递增 |

共13种有效编码。图中若使用MOVI/ADDI，可理解为MOV/ADD的立即数形式；正式说明统一采用上表助记符。INP/OUP是本项目定义的助记符，不表示所有RISC或ARM处理器都使用这些指令。

加减结果保留低16位，不设置进位或溢出标志。除CMP外，所有指令保持Z不变。除成功跳转外，PC按模256加1。

## 5. Controller

控制器由三个组合逻辑部分组成：

1. 字段提取：从16位指令取出Opcode、Rd、Rs及imm8/port。
2. 操作码译码：识别当前指令。
3. 控制信号生成：控制数据选择、ALU功能以及寄存器和外设写入。

| 控制信号 | 用途 |
|---|---|
| alu_src | ALU操作数B选择寄存器值或立即数 |
| alu_op[2:0] | 选择PASS B、ADD、SUB、AND、OR、XOR |
| wb_sel | 写回数据选择ALU结果或I/O读数据 |
| reg_write | 通用寄存器写使能 |
| z_write | Z写使能，仅CMP有效 |
| jump / branch_z | 无条件跳转/根据Z条件跳转 |
| io_re / io_we | I/O读/写控制 |

这三个部分不是三个时钟周期。当前控制器不包含多周期执行状态机，也不在取指和执行之间插入额外的指令阶段寄存器。

## 6. Datapath与五个功能步骤

五个步骤用于说明功能，不是五级流水线，也不意味着每条指令需要五个时钟周期。

| 功能步骤 | 本项目的数据流 |
|---|---|
| IF：取指 | PC输出地址，CPU核外指令存储器组合读出16位指令 |
| ID：译码及读寄存器 | Controller译码，寄存器组读取R[Rd]、R[Rs]，立即数零扩展 |
| EX：执行 | ALU执行运算；CMP经零检测产生Z的新值；跳转逻辑确定下一PC |
| MEM/I/O：访问 | 本版无普通数据访存；INP/OUP通过独立接口访问GPIO外设 |
| WB：写回 | ALU结果或I/O读数据经写回MUX送入Rd写端口 |

### 6.1 运算与写回路径

```text
R[Rd] ────────────────────→ ALU操作数A
R[Rs] / 零扩展imm8 → B MUX → ALU操作数B
ALU结果 / I/O读数据 → 写回MUX → 寄存器组Rd
```

MOV使用ALU的PASS B功能。ADD/SUB/AND/OR/XOR写回ALU结果；INP写回I/O读数据。运算结果不需要经过外设模块。

### 6.2 CMP、Z和跳转路径

CMP借助ALU执行减法，零检测判断结果是否为0。执行CMP时，仅将比较结果保存到Z，不修改通用寄存器。

```text
take_jump = jump OR (branch_z AND Z)
PC_next   = take_jump ? imm8 : ((PC + 1) modulo 256)
```

JZ使用前面CMP已保存的Z，不使用当前JZ指令期间ALU的临时零检测结果。PC不是通用运算结果的最终目的地；它独立选择下一指令地址。

### 6.3 单周期时序

一个周期开始后，PC及寄存器状态驱动组合取指、译码、运算、I/O读取和写回选择。在周期结束的有效上升沿：

- PC更新为PC_next。
- reg_write有效时，Rd写入结果。
- z_write有效时，Z写入比较结果。
- 合法OUP的写使能有效时，对应外设寄存器写入数据。

这些状态更新在同一个边沿发生，不是依次耗费多个周期。时钟周期必须覆盖最长组合路径。指令存储器按组合读实现；若改用同步读存储器，必须重新设计取指时序，不能直接替换。

## 7. CPU边界接口

方向均相对于CPU Core。信号不是外部封装引脚数量。

| 信号 | 位宽 | 方向 | 用途 |
|---|---:|---|---|
| clk / rst | 各1 | 输入 | 时钟及复位 |
| instruction | 16 | 输入 | 指令存储器返回值 |
| mem_addr | 8 | 输出 | PC取指地址 |
| io_addr | 8 | 输出 | 指令中的port字段 |
| io_wdata | 16 | 输出 | R[Rs] |
| io_rdata | 16 | 输入 | 外设读数据 |
| io_re / io_we | 各1 | 输出 | 外设读写控制 |

当前GPIO外设采用组合读取、边沿写入，不需要等待状态。未来若连接有可变响应延迟的外设，需增加握手/等待机制并重新考虑单周期约束。

## 8. 8位GPIO外设

GPIO是CPU核外的外设。CPU通过INP/OUP访问其寄存器；外设通过8个双向缓冲器连接顶层gpio[7:0]。

| 端口地址 | 名称 | 访问 | 含义 |
|---|---|---|---|
| 0x10 | GPIO_OUT | 读/写 | 8位输出锁存值；读操作返回锁存值 |
| 0x11 | GPIO_IN | 只读 | 同步后的8位引脚采样值 |
| 0x12 | GPIO_DIR | 读/写 | 每位1=输出，0=输入 |

OUP仅使用io_wdata[7:0]，高8位忽略。INP返回值高8位补0。未映射地址读取返回0；向只读或未映射端口写入不产生副作用。

GPIO_OUT、GPIO_IN和GPIO_DIR管理同一组8个引脚，不是各占8个引脚。不同引脚可以同时作为输入或输出；同一引脚不允许CPU和外部设备同时独立驱动相反电平。输入模式下CPU输出缓冲器为高阻态。

外部异步输入先通过同步器进入CPU时钟域，因此INP读取的是同步后的值，不是零延迟的外部电平。机械按键还需要消抖；多个同时变化的数据位若要求整体一致采样，需要另外设计握手机制。

上版方案中的专用LED端口0x00、显示端口0x01未纳入这版8位GPIO基线，作为可选后续扩展，不计入当前接口承诺。演示时可以将选定GPIO连接到适当的输入/输出设备，具体板上连接必须先核对原理图。

## 9. 复位与安全初态

复位清零PC、R0～R3、Z、GPIO_OUT及GPIO_DIR，抑制外设写入。GPIO_DIR=0使全部GPIO默认为输入，避免刚上电时误驱动外部设备。

将引脚切换为输出时，建议先写GPIO_OUT，再设置GPIO_DIR。复位采用同步还是异步方式及其释放处理，在RTL接口规范阶段统一确定。

## 10. 最小功能演示

以下为汇编含义示例，不代表已提供可执行的汇编器工具：

```text
MOV R0, #0x00
OUP 0x10, R0       ; 先设置输出锁存值
MOV R0, #0x0F
OUP 0x12, R0       ; gpio[3:0]输出，gpio[7:4]输入
MOV R1, #0x05
OUP 0x10, R1       ; 低4位输出0101
INP R2, 0x11      ; 读取8位同步后的引脚电平
MOV R3, #0x00
CMP R2, R3        ; 判断读取值是否为0，更新Z
```

跳转和循环演示可在上述基础上加入JZ/JUMP。物理电平与LED亮灭的对应关系、是否允许某引脚输出等，需要按板卡原理图确定。

## 12. 下一步工作

1. 固定接口及控制真值表：逐条确认ALU操作、MUX选择、写使能、默认值和复位规则。
2. 编写RTL模块：Controller、Register File、ALU、PC/Z、指令存储器、GPIO外设及系统顶层。
3. 编写TestBench：覆盖全部有效指令、保留操作码、CMP/Z保持、跳转成功/失败、PC回绕、GPIO读写与复位。
4. 检查单周期时序与综合结果：确认组合读存储器实现方式，验证最长路径能满足目标时钟。
5. 核对EES331原理图并分配物理引脚：确定GPIO可用管脚、I/O电压标准、时钟和复位来源，再编写约束文件。
6. 上板验证：先验证复位和简单GPIO输出，再验证输入采样及条件跳转程序。

目前8个GPIO指的是功能引脚数量；封装管脚编号、目标频率、板上设备接线以及RTL验证结果均尚待确认。
