# 国际象棋：双人 / 自制 CPU 人机

2026-11-12：已生成 `reports/MiniRISC16_Arcade4K.bit`。50 MHz 时序通过：WNS +4.734 ns、WHS +0.034 ns；DRC 0 错误。完整验证记录见 `reports/VERIFICATION.md`。

棋盘、轮次、全部走法验证、将军、终局判断和 AI 落子决策均由 FPGA 上的 MiniRISC-16 汇编执行。电脑只发送模式、选择的起点、终点和升变棋子，接收状态并绘制棋盘。

人机模式玩家执白先手，CPU 执黑。AI 枚举全部合法走法，按吃子收益、升后收益、中心位置和目标格受到攻击时的棋子损失评分，选分数最高的一步；同分选扫描顺序最前者。兵/马/象/车/后价值为 10/30/30/50/90，升后增加80，中心文件和横线各加2。AI 自动升后。这是确定性的单步评分 AI，不进行多层搜索，也不保证能找出所有将杀或避免战术陷阱。

已实现：六种棋子走法、路径阻挡、吃子、禁止己方王被将军的走法、王车易位（含经过将军格的限制和易位权更新）、吃过路兵、升后/车/象/马、将军、将死、逼和、终局禁止继续走棋。

范围：第一阶段双人版，不包含重复局面、50/75 回合、死局和棋裁定、棋钟或认输/协议和棋。这些情况不会自动结束对局，可自行约定后重开。

## 第一次使用：先更换硬件 bitstream

当前含 AI 的程序需要 2792 条指令，旧的 1K Runtime 无法运行。新硬件将 PC、JMPA 目标和程序 RAM 地址扩展为 12 位，容量 4096×16；数据 RAM 仍为 256×16。棋盘用 0x88 表示法，RAM 0..127；变量为 128..210。

新硬件使用 MMCM 将板上 100 MHz 转为 50 MHz 系统时钟。串口分频为 434，基础定时器和数码管扫描分频同步减半，串口仍为 115200 8N1。100 MHz 的 4K 版本未通过时序，记录保留在 reports/100mhz_attempt。

1. J3 接电脑，用 Vivado Hardware Manager 下载本目录 `reports/MiniRISC16_Arcade4K.bit`。
2. J8 上方 PL UART USB 接电脑，确认实际 COM 编号。
3. 在 runtime_system 目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\arcade_launcher.ps1 -PortName COM3
```

4. 将 SW7=1，在菜单按 6 选择 CHESS，然后 Enter 上传。上传器先查询硬件容量，发现旧 1K 硬件会停止，不会写入棋局程序。
5. 终端提示后，将 SW7=0 并按 Enter，再按 1 选择双人、按 2 选择人机。

已发布的 `MiniRISC16_Arcade4K.bit` 仍内置上一版双人程序（协议6）；此次 AI 升级通过菜单上传最新 `chess.mem`（协议7），无需重新生成或更换已经下载的 4K 硬件。直接启动新版终端而没有上传新版程序会提示版本不匹配。断电或重新下载原 bitstream 后需要再次上传。已有 1K 游戏程序仍可经原 Loader 上传。

## 操作

方向键 / WASD 移动光标；空格 / Enter 先选棋子，再选目标格。Esc 取消选择，R 重开当前模式，M 返回模式选择（选择后新开棋局），Q 返回游戏菜单。升变时 Q/R/B/N 选后/车/象/马，Enter 默认后。

白方为大写 P/N/B/R/Q/K，黑方为小写；底部为白方第一横线。王车易位选择王的两格移动，吃过路兵选择兵的斜前方目标格。非法走法不改变棋盘或轮次。电脑仅显示 CPU 返回的“非法走法”“将军”“将死”“逼和”。

## 构建与测试

从本目录运行：

```powershell
.\tools\build.ps1
.\tools\build.ps1 -Simulate
.\tools\build.ps1 -Hardware
```

可用 `-VivadoRoot` 指定安装路径，`-BuildRoot` 指定英文临时构建目录。本机 Vivado 在原中文路径综合时异常退出，英文路径单线程构建可继续，因此构建脚本会准备独立英文路径并把报告复制回来。

`build.cjs` 是规则源代码生成器，生成 `program/chess.asm`；`assemble4k.ps1` 生成机器码、列表和硬件初始化 RAM。`hardware` 中的覆盖模块由专用构建脚本选择，不覆盖原有 runtime_system/rtl，因此旧 1K 构建流程仍保留。

验证覆盖：初始局面合法走法数量 20/400、Kiwipete 48、非法走法、被牵制棋子、四种升变、黑方升变、双向易位、禁止穿过将军格易位、吃过路兵以及导致己方王暴露时的拒绝、将死与终局锁定、逼和、帧校验。机器码模型从实际 .mem 执行；真实 XSim RTL 另外验证启动、超过 1K 的 PC、四步将死和帧校验。Loader RTL 验证容量查询、完整 4096 地址写入、旧 1024 字上传及超容量拒绝。

新增 `verify_ai.cjs` 验证模式/重开、自动应答、非法玩家输入不触发 AI、吃子评分、受攻击惩罚、应将、自动升后、易位/吃过路兵试走恢复和终局不再落子。真实 RTL 测试已追加模式切换和玩家 e2-e4 后 CPU 自行完成黑方应答。`reports/AI_VERIFICATION.md` 记录本次升级；`reports/VERIFICATION.md` 保留此前硬件 bitstream 的验证记录。

尚未进行实板和真实串口联调。仿真通过不等于已在实物上验收。

## 串口协议

命令：240 重开当前模式；241 查询；242 后跟三个字节 from、to、promotion；244 选择人机并重开；245 选择双人并重开。格子为 `rank*16+file`，rank/file 均为 0..7，a1=0，h8=119。promotion 为 0默认后、2马、3象、4车、5后。移动请求含完整三个参数后 CPU 才开始处理。人机模式在黑方应答和终局检查完成后回复；玩家走出将死或逼和时立即回复。

回复 70 字节：A5，版本7，sideMode（bit3：0白/1黑；bit6：0双人/1人机），status(0正常/1将军/2白胜/3黑胜/4逼和)，error(0正常/1非法)，64格棋盘(a1..h1,a2..h8)，前69字节 XOR。棋子低3位 1兵/2马/3象/4车/5后/6王；黑棋另加8；空格0。

Loader 查询命令 55 49，返回 MR16、容量高/低字节、状态；新容量1000十六进制。上传包沿用 55 4C、16位字数、big-endian程序字、16位累加校验。原始交接包的 SHA256SUMS 不覆盖本次新增文件，菜单原哈希也已改变。
